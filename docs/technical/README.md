# Technical documentation

This folder holds architecture notes: how the code is structured and how systems work together.
It describes the current state. It does not record decisions.

- **Decisions** that apply beyond one task → `docs/adr/` (ADRs).
- **Decisions** that only affect one task or plan → that plan, e.g. `docs/kits/<kit>-plan.md`.
- **Game design** (what and why) → Notion.

## What goes here

- overviews of systems and how they connect (e.g. which service owns which data)
- module and folder conventions that go beyond `CLAUDE.md`
- how-tos for developers and agents (running tests locally, building a Place, Studio setup)

Update a note in the same PR that changes the architecture it describes (`CLAUDE.md`, Definition of Done, point 6).
Link the ADR a note is based on instead of repeating its reasoning.
